中日跨境配送管理系统计划

目前希望把现有的“中国收货 → 航班运输 → 日本到货 → 日本配送”流程逐步数字化，减少现在依赖 Excel、电话和人工沟通的问题。

一、主要解决的问题
目前主要存在：

Excel 查询客户地址、电话比较麻烦
客户名称相似，容易弄混
同一客户可能有多个配送地址
部分地址不明确
客户指定配送时间容易遗漏
客户的特殊配送要求不容易传达给司机
中国取货和日本配送的信息比较分散
人工分配司机比较耗时
客户无法方便地查询订单配送状态
后期重量和费用计算也需要人工处理
二、整体流程
中国客户下单
↓
填写货物重量、数量、照片、配送要求
↓
中国端安排取货
↓
中国工作人员确认取货、确认实际重量、上传照片
↓
货物通过航班运输到日本
↓
日本到货
↓
管理员安排司机
↓
司机通过手机网页查看配送任务
↓
司机配送
↓
更新配送状态、上传配送照片
↓
配送完成
↓
客户查看订单完成情况

三、Address ID
给每一个实际配送地址建立唯一的 Address ID。

例如：

ABC公司

ADR-000001：总部
ADR-000002：东京仓库
ADR-000003：东京工厂
以后订单、配送任务、司机端、地图等都通过 Address ID 关联。

这样即使同一个客户有多个配送地点，也不会因为客户名称相同而弄错。

地址信息可以保存：

地址
电话
联系人
配送时间
搬入口
停车信息
配送注意事项
经纬度
以后司机打开任务后，直接看到完整的信息，不需要再查 Excel。

四、中国客户端
中国客户登录后可以：

管理自己的配送地址
创建订单
填写货物名称
填写箱数
填写重量
上传货物照片
填写特殊要求
查看订单状态
订单生成 Order ID，并关联 Customer ID 和 Address ID。

五、中国取货端
中国工作人员可以看到需要取货的订单。

取货时可以：

查看客户信息
查看取货地址
查看货物信息
查看客户申报重量
确认实际货物
填写实际重量
上传取货照片
确认取货完成
重量需要区分：

客户申报重量
实际取货重量
计费重量

例如：

客户申报：25kg
实际取货：27kg

后期可以根据公司的收费规则决定最终使用哪个重量进行计费。

六、日本管理端
内部管理员可以统一管理：

客户
配送地址
订单
中国取货
日本到货
司机
车辆
配送任务
异常订单
订单状态可以分为：

待取货 → 中国取货中 → 中国取货完成 → 运输中 → 日本到货 → 待配车 → 已配车 → 配送中 → 配送完成

第一阶段先采用人工配车。

七、司机端
司机使用手机网页。

每天登录后可以直接看到自己的配送任务：

客户名称
Address ID
地址
电话
联系人
配送时间
配送备注
箱数
重量
并可以直接：

打开地图导航
拨打客户电话
开始配送
完成配送
提交异常
上传照片
司机开始配送后，手机可以定期上传GPS位置。

不需要高频实时定位，例如每30～60秒更新一次即可。

八、管理员地图
管理后台接入 Google Maps。

管理员可以在地图上看到目前正在配送的司机。

例如：

司机A → 当前订单 → 客户A
司机B → 当前订单 → 客户B
司机C → 当前订单 → 客户C

点击司机后可以看到：

当前司机
当前订单
配送地址
配送状态
最后更新时间
这样早上5～8点进行配送安排时，可以直接掌握整个配送情况。

九、顾客看到的内容
顾客不需要看到司机的精确GPS位置。

主要显示：

订单状态
中国取货状态
日本运输状态
日本配送状态
预计到达时间
大致距离
例如：

“配送中”

“距离目的地约8km”

“预计10:30左右到达”

这样既能让客户了解配送进度，也不需要公开司机的精确位置。

十、后期费用和会计
系统后期可以根据订单重量自动计算费用。

基本流程：

订单
→ 实际重量
→ 计费规则
→ 配送费用
→ 账单
→ 会计系统

因此从第一阶段开始，就需要把重量数据保存好。

后期可以增加：

按重量计费
客户账单
月度费用统计
付款状态
会计系统连接
十一、第一阶段重点
第一阶段不追求一次做得很复杂，主要先解决现在最痛的几个问题：

① Address ID统一管理地址

② 中国客户在线下单

③ 中国端确认取货

④ 日本管理员统一管理订单和司机

⑤ 司机手机端查看配送任务

⑥ Google地图查看司机当前位置

⑦ 顾客查看订单和配送状态

先把整个流程跑通。

之后有了实际订单数据，再继续开发：

自动配车 → 自动路线规划 → 路线优化 → 自动计费 → 会计系统

这样开发风险和成本都会比较低，也能根据实际业务不断调整系统。
