【拆卡直播间小程序——业务流程】

一、用户账户

1. 用户进入微信小程序。
2. 用户通过微信登录。
3. 系统创建或识别用户账户。
4. 用户账户可以关联：
   - 当前排队/服务状态
   - 购物车
   - 待结算订单
   - 历史订单

二、进入直播间

1. 用户进入拆卡直播间。
2. 查看当前直播状态。
3. 查看当前排队情况。
4. 用户可以选择加入排队。

三、加入排队

1. 用户点击“加入排队”。
2. 系统创建一次新的服务排队记录。
3. 系统分配排位号。
4. 服务状态变为 WAITING（等待中）。
5. 用户可以查看：
   - 当前排位号
   - 前面等待人数
   - 当前服务状态
   - 预计等待情况（如果系统提供）

四、等待期间

用户处于 WAITING 状态时：

1. 可以继续等待。
2. 可以浏览直播间商品。
3. 可以将商品加入购物车。
4. 可以修改购物车中的商品数量。
5. 可以查看购物车。
6. 暂时不能正式下单。
7. 用户可以主动退出排队。

五、退出排队

1. 用户点击“退出排队”。
2. 当前排队记录结束。
3. 排位状态变为 CANCELLED（已取消）。
4. 用户退出当前队列。
5. 用户购物车中的商品继续保留。
6. 用户以后可以重新加入排队。
7. 重新排队时创建新的排队记录，并获得新的排位号。

六、店员叫号

1. 店员在员工后台查看当前排队队列。
2. 店员选择下一位用户。
3. 系统将该用户状态变为 CALLED（已叫号）。
4. 用户收到叫号通知。
5. 用户响应叫号后：
   CALLED → ACTIVE（服务中）。
6. 用户没有响应时：
   店员可以选择“跳过”。
7. 被跳过的用户状态变为 SKIPPED（已过号）。
8. 过号后不能恢复原来的排位。
9. 用户需要重新加入排队。
10. 重新排队后获得新的排位号。
11. 原来的购物车商品继续保留。

七、服务开始

1. 用户响应叫号。
2. 排队状态变为 ACTIVE（服务中）。
3. 用户正式进入本次拆卡服务。
4. 用户可以：
   - 浏览商品
   - 加入购物车
   - 修改购物车
   - 删除购物车商品
   - 查看已经下单的订单
   - 继续下单

八、购物车

1. 购物车属于用户账户。
2. 购物车独立于排队状态。
3. 用户在 WAITING 状态可以加入购物车。
4. 用户在 ACTIVE 状态可以加入购物车。
5. 用户掉线后购物车继续保留。
6. 用户退出排队后购物车继续保留。
7. 用户过号后购物车继续保留。
8. 用户结束服务后购物车不会自动下单。
9. 员工强制结束服务后购物车也不会自动下单。
10. 只有用户主动点击“下单”，购物车中的商品才会生成正式订单。

九、主动下单

1. 用户在 ACTIVE 状态下进入购物车。
2. 用户确认需要购买的商品。
3. 用户点击“下单”。
4. 系统根据当前购物车商品创建正式订单。
5. 订单状态变为 UNPAID（待支付）。
6. 已经生成订单的商品从当前购物车中移除或标记为已下单。
7. 用户可以继续向购物车加入新的商品。
8. 用户可以再次下单。
9. 一次服务期间允许产生多个订单。
10. 下单不代表立即支付。
11. 用户可以之后再进行支付。

十、服务期间掉线

1. 用户在 ACTIVE 状态时掉线、退出小程序或网络中断。
2. 系统不自动结束服务。
3. 系统不自动下单。
4. 系统不自动清空购物车。
5. 系统不自动取消已经产生的订单。
6. 当前服务状态保持不变。
7. 用户重新进入小程序并登录后：
   - 恢复用户账户
   - 恢复当前服务状态
   - 恢复购物车
   - 恢复待支付订单
   - 恢复历史订单

十一、用户主动结束服务

1. 用户在 ACTIVE 状态下点击“结束服务”。
2. 系统确认用户是否确定结束服务。
3. 用户确认后：
   ACTIVE → FINISHED（服务结束）。
4. 本次排队/服务记录结束。
5. 购物车不会自动下单。
6. 购物车不会自动支付。
7. 购物车不会因为结束服务而自动清空。
8. 已经主动下单产生的订单继续保留。
9. 待支付订单继续保留在用户个人中心。
10. 用户以后可以在个人中心查看并支付待结算订单。

十二、员工强制结束服务

1. 员工可以在后台查看当前 ACTIVE 用户。
2. 员工可以选择“强制结束服务”。
3. 系统将当前服务状态变为 FINISHED。
4. 不自动将购物车商品生成订单。
5. 不自动支付。
6. 不删除购物车。
7. 已经产生的订单继续保留。
8. 待支付订单继续保留在用户个人中心。

十三、订单

1. 订单只在用户主动点击“下单”时生成。
2. 一个用户一次服务可以产生多个订单。
3. 订单生成后状态为 UNPAID（待支付）。
4. 订单与当前排队/服务状态相互独立。
5. 服务结束不会自动关闭订单。
6. 服务结束不会自动支付订单。
7. 用户可以在个人中心查看待支付订单。
8. 用户可以在个人中心主动进行支付。
9. 支付成功后：
   UNPAID → PAID（已支付）。
10. 已支付订单进入历史订单。

十四、个人中心

个人中心主要包含：

1. 用户信息
2. 当前服务
3. 当前购物车
4. 待结算订单
5. 历史订单

待结算订单：

- 查看订单详情
- 查看商品
- 查看订单金额
- 点击“立即支付”
- 完成微信支付

历史订单：

- 查看历史订单
- 查看订单详情
- 查看商品明细
- 查看订单金额
- 查看支付状态
- 查看订单时间

十五、排队状态

WAITING
等待中

WAITING → 用户退出 → CANCELLED

WAITING → 店员叫号 → CALLED

CALLED → 用户响应 → ACTIVE

CALLED → 用户无响应 → SKIPPED

SKIPPED → 用户重新排队 → 新的 WAITING

ACTIVE → 用户结束服务 → FINISHED

ACTIVE → 员工强制结束 → FINISHED

十六、核心业务原则

1. 排队决定用户当前的服务资格。
2. WAITING 状态可以加入购物车，但不能正式下单。
3. ACTIVE 状态可以正式下单。
4. 购物车属于用户账户，不属于某一个排位号。
5. 退出排队不会删除购物车。
6. 过号不会删除购物车。
7. 过号必须重新排队并获得新的排位号。
8. 掉线不会改变服务状态。
9. 掉线不会自动下单。
10. 结束服务不会自动下单。
11. 员工强制结束不会自动下单。
12. 只有用户主动点击“下单”才会产生订单。
13. 一次服务可以产生多个订单。
14. 下单和支付是两个独立动作。
15. 服务结束和订单支付也是两个独立动作。
16. 用户可以在服务结束后，通过个人中心处理待支付订单。
17. 支付完成的订单进入历史订单。
